# Чек-лист отладки перед коммерческим запуском шаблона

Прогонять целиком после любой правки `index.html`/`src/index.js`, и минимум
один раз перед тем как отдавать шаблон новому клиенту.

## 0. Подготовка (один раз)

```bash
cp .dev.vars.example .dev.vars
```

Терминал 1 (Worker/API):
```bash
npx wrangler dev
```
Терминал 2 (статика):
```bash
npx wrangler pages dev . --port 8788
```
Терминал 3 (тестовые данные, один раз после старта Worker'а):
```bash
node test-data/seed.js
```
Открыть: `http://127.0.0.1:8788/index.html`
Пароли: `dev-guest-2026` / `dev-admin-2026` (см. `.dev.vars.example`)

## 1. Сквозной прогон установки (install-flow) — самое важное

Реальная причина, по которой этот чек-лист появился: весь `install.bat →
setup.js → wrangler.toml → src/index.js` был нерабочим цепочкой несколько
итераций подряд, и никто не проверял его целиком до конца.

- [ ] На **чистой** копии репозитория (без `.wrangler/`, без ранее
      созданных `node_modules/`) дважды кликнуть `install.bat`
- [ ] Дошёл ли процесс до вопросов про пароли, не упав раньше
- [ ] `node setup.js` реально находит и обновляет `wrangler.toml`
      (не падает на `ENOENT`)
- [ ] Шаг создания KV (`npx wrangler kv namespace create TREE_KV`)
      либо срабатывает, либо корректно просит вставить ID вручную
- [ ] Аналогично для R2-бакета (шаг 4b) — создаётся автоматически или
      просит имя вручную
- [ ] `npx wrangler deploy` реально находит `src/index.js` как `main`
- [ ] После деплоя Worker'а — подстановка `workerUrl` в `index.html`
      сработала автоматически (не выводит "впишите вручную")
      — если увидите этот вывод, проверьте `htmlCandidates` фильтр в
      `setup.js` (должен исключать `welcome.html`, не искать `admin.html`)

## 5a. Еврейский календарь, напоминания, выбор еврейской даты и значки контактов

В фикстуре `seed.js` нет еврейских дат. Чтобы проверить файл 🕎 и срок его действия, впишите еврейскую дату одному человеку: «Исправить» → «Дата рождения (евр.)» или «Дата смерти (евр.)».

### Окно «Семейные напоминания» (🔔, 📅, 🕎)

- [ ] Три кнопки (🔔, 📅, 🕎) открывают одно и то же окно; кнопка диагностики открывает диагностику, как раньше
- [ ] Поле «Кто вы в этом дереве?» принимает имя из списка; пока человек не выбран, виден жёлтый текст о том, что радиус не применяется
- [ ] Кнопка «Это я» в панели человека: она становится неактивной с подписью «Это я (выбрано)», в окне напоминаний поле заполнено
- [ ] Круги: «Родственников до уровня» и «Более дальних, до уровня» меняются, значения сохраняются после закрытия и повторного открытия окна (хранятся в браузере)
- [ ] В панели человека есть список из четырёх решений (как по радиусу, всегда с напоминанием, без напоминания, никогда); число людей в окне меняется
- [ ] Удаление человека убирает его из настроек напоминаний
- [ ] Скачивание дней рождения: имя файла начинается с `family-`, в файле `PRODID` содержит название семьи из `TREE_CONFIG`
- [ ] Скачивание еврейских дат (нужна хотя бы одна еврейская дата): файл создаётся; в режиме «без напоминания» блоков `BEGIN:VALARM` меньше, чем `BEGIN:VEVENT`
- [ ] Ссылка «Справка об этом окне» открывает справку поверх окна; в справке «?» есть два раздела про напоминания
- [ ] RU, EN, HE: подписи окна переводятся, иврит выровнен вправо; на узком экране окно прокручивается

### Срок действия еврейского календаря

- [ ] После скачивания файла у кнопки 🕎 в подсказке виден срок «действует до …»
- [ ] В панели человека с еврейской датой смерти видна строка срока действия (только после скачивания файла)
- [ ] Когда срок подходит к концу, кнопка 🕎 подсвечивается (класс `hebcal-due`), а при открытии страницы подсказка обновляется

### Выбор еврейской даты и синхронизация («Исправить»)

- [ ] Вместо текстовых полей еврейских дат стоят списки (день, месяц, год числом и буквами), справа виден предпросмотр записи
- [ ] Неполная дата (например, только месяц) при сохранении даёт сообщение об ошибке, форма не сохраняется
- [ ] Запись нестандартного вида показывается как есть, рядом кнопка «Выбрать заново»
- [ ] Галочка «Вычислять по григорианской дате» видна только при полной григорианской дате
- [ ] При открытии формы галочка стоит сама, если еврейская дата совпадает с григорианской (в том числе после заката); она не стоит, если еврейской даты нет, дата расходится или Адар неоднозначен
- [ ] Включение галочки подставляет еврейскую дату и блокирует списки; «После захода солнца» сдвигает дату на день; «Изменить вручную» снимает блокировку, значение остаётся
- [ ] Смена григорианской даты при включённой галочке пересчитывает еврейскую

## Известные открытые разрывы с рабочим проектом (не путать с новыми багами)

| Разрыв | Статус |
|---|---|
| Нет кнопки × в окне логина | не портировано из `mostovoy-tree` |
| Смена гостевого пароля недостижима из UI | backend есть, фронтенда нет |
| Язык не переключается в окне логина | ограничение в ОБОИХ проектах (не регрессия шаблона) |
| `PLACEHOLDER_KV_ID`/`PLACEHOLDER_PHOTOS_BUCKET_NAME` были в невалидном для Cloudflare формате (заглавные+подчёркивания) — `wrangler dev` отказывался стартовать даже локально | исправлено (заменены на `placeholder-kv-id`/`placeholder-photos-bucket-name`) |
| `FAMILY_NAME_RU`/`FAMILY_SLUG`/`CALENDAR_UID_DOMAIN` никогда не заполняются `setup.js` даже для реального клиента — остаются буквальным текстом `PLACEHOLDER_...` в именах файлов календаря/контактов | найдено, не исправлено — влияет только на косметику (имена скачиваемых файлов), не блокирует запуск |

При обнаружении новых пунктов — дописывать сюда, не терять в переписке.
