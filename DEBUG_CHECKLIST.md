# Чек-лист отладки перед коммерческим запуском шаблона

Прогонять целиком после любой правки `index.html`/`src/index.js`, и минимум
один раз перед тем как отдавать шаблон новому клиенту.

## 0. Подготовка (один раз)

```bash
cp .dev.vars.example .dev.vars
```

Терминал 1 (Worker/API):
```bash
npx wrangler dev
```
Терминал 2 (статика):
```bash
npx wrangler pages dev . --port 8788
```
Терминал 3 (тестовые данные, один раз после старта Worker'а):
```bash
node test-data/seed.js
```
Открыть: `http://127.0.0.1:8788/index.html`
Пароли: `dev-guest-2026` / `dev-admin-2026` (см. `.dev.vars.example`)

---

## 1. Сквозной прогон установки (install-flow) — самое важное

Реальная причина, по которой этот чек-лист появился: весь `install.bat →
setup.js → wrangler.toml → src/index.js` был нерабочим цепочкой несколько
итераций подряд, и никто не проверял его целиком до конца.

- [ ] На **чистой** копии репозитория (без `.wrangler/`, без ранее
      созданных `node_modules/`) дважды кликнуть `install.bat`
- [ ] Дошёл ли процесс до вопросов про пароли, не упав раньше
- [ ] `node setup.js` реально находит и обновляет `wrangler.toml`
      (не падает на `ENOENT`)
- [ ] Шаг создания KV (`npx wrangler kv namespace create TREE_KV`)
      либо срабатывает, либо корректно просит вставить ID вручную
- [ ] Аналогично для R2-бакета (шаг 4b) — создаётся автоматически или
      просит имя вручную
- [ ] `npx wrangler deploy` реально находит `src/index.js` как `main`
- [ ] После деплоя Worker'а — подстановка `workerUrl` в `index.html`
      сработала автоматически (не выводит "впишите вручную")
      — если увидите этот вывод, проверьте `htmlCandidates` фильтр в
      `setup.js` (должен исключать `welcome.html`, не искать `admin.html`)

## 2. Локализация (RU/EN/HE)

- [ ] Переключение языка обновляет: тулбар, кнопки, подписи форм
- [ ] Переключение языка **НЕ** обновляет текст модалки логина (пароль) —
      это ИЗВЕСТНОЕ ограничение (текст захардкожен на русском в
      `showLoginForm()`), не баг, но убедитесь что оно не ухудшилось
- [ ] RTL для иврита не ломает раскладку тулбара/панели/модалок
- [ ] Иврит-даты (`birth_he`/`death_he`) отображаются `dir="rtl"`

## 3. Модалка логина (окно пароля) — известный разрыв с рабочим проектом

- [ ] **Есть ли кнопка × в правом верхнем углу?** (на момент написания —
      НЕТ, в отличие от `mostovoy-tree`, где есть `#login-close` +
      обработчики клика вне окна и `Escape`) — если это ещё не портировано,
      не считайте это новым багом, но и не забывайте
- [ ] Ввод неверного пароля показывает понятную ошибку, не молчит
- [ ] После успешного логина иконка 🔑 меняется на 🔓 (admin) / 👤 (guest)

## Известные открытые разрывы с рабочим проектом (не путать с новыми багами)

| Разрыв | Статус |
|---|---|
| Нет кнопки × в окне логина | не портировано из `mostovoy-tree` |
| Смена гостевого пароля недостижима из UI | backend есть, фронтенда нет |
| Язык не переключается в окне логина | ограничение в ОБОИХ проектах (не регрессия шаблона) |
| `PLACEHOLDER_KV_ID`/`PLACEHOLDER_PHOTOS_BUCKET_NAME` были в невалидном для Cloudflare формате (заглавные+подчёркивания) — `wrangler dev` отказывался стартовать даже локально | исправлено (заменены на `placeholder-kv-id`/`placeholder-photos-bucket-name`) |
| `FAMILY_NAME_RU`/`FAMILY_SLUG`/`CALENDAR_UID_DOMAIN` никогда не заполняются `setup.js` даже для реального клиента — остаются буквальным текстом `PLACEHOLDER_...` в именах файлов календаря/контактов | найдено, не исправлено — влияет только на косметику (имена скачиваемых файлов), не блокирует запуск |

При обнаружении новых пунктов — дописывать сюда, не терять в переписке.
